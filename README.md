# VoWiFi VPN

为本地 SIP 电话项目提供云端 WireGuard 接入和独立的 SIP / RTP 端口转发。

云端负责公网入口、VPN 客户端和端口映射；SIP 账号、注册、通话和设备由本地 SIP 项目管理。

## 1. 部署前准备

- Ubuntu 24.04 LTS，amd64 或 arm64，使用 systemd。
- 可通过 SSH 管理的云主机，具备公网 IPv4、root / sudo 权限及 WireGuard 支持。
- 使用没有其他 WireGuard / 同端口服务冲突的主机；安装器会先检查现有环境。

在云厂商安全组和服务器防火墙中放行：

| 协议 / 端口 | 用途 |
| --- | --- |
| TCP 80、443 | HTTPS 证书、管理面板和接入接口 |
| UDP 51820 | WireGuard 隧道 |
| 每个客户端分配的 TCP / UDP 端口段 | SIP 与 RTP 转发，例如 `20000–29999` |

SSH 管理端口以服务器实际设置为准。内部管理端口 `51821`、`51822` 无需对外开放。

## 2. 一键部署

在云服务器的交互式 SSH 终端执行：

```bash
curl -fsSL https://raw.githubusercontent.com/Rykvo/VoWiFi-VPN/main/deploy.sh | sudo bash -s -- install
```

按提示确认公网 IPv4，设置管理员账号和密码。安装器会配置依赖、WireGuard、转发规则、HTTPS 和系统服务。

部署完成后访问：

```text
https://服务器公网IP/gly
```

HTTPS 证书会自动申请；首次访问需等待证书签发完成。

## 3. 连接本地 SIP 项目

1. 登录云端面板，点击「新建客户端」。
2. 填写名称和独立的公网端口段，例如 `20000–29999`；不同客户端的端口段不能重叠。
3. 点击该客户端的「连接」，再点击「生成接入码」。未生成时，接入码的「复制」按钮保持禁用。
4. 将弹窗里的**接入地址**和**接入码**填写到本地 SIP 项目的云端接入设置中。
5. 本地后端保存配置并启动 WireGuard，随后检查隧道握手、SIP 注册和双向通话。

接入码用于连接云端，本地 SIP 账号和密码由本地项目管理。不要把接入码、WireGuard 私钥或完整配置发到公开日志和问题反馈中。

本地项目对接与配置校验见 [接入接口说明](app/web/integration.md)。

### 可选：使用域名

在面板「域名设置」中配置：

| 设置 | 用途 |
| --- | --- |
| 面板域名 | 访问 `https://面板域名/gly` |
| SIP 域名 | 接入地址和本地 SIP 项目对外使用的 SIP 地址 |

SIP 域名须仅做 DNS 解析并指向云服务器公网 IPv4，不开启 Cloudflare 代理。没有配置域名时可以使用公网 IP；接入地址始终以云端连接弹窗显示的完整地址为准。

## 4. 日常更新

```bash
sudo vowifi-vpn update
```

更新保留账号、密钥、接入码和客户端配置。正常运行的 VPN 容器不会仅因页面或程序更新被主动重启。

## 5. 连接诊断与日志

检查云端状态并查看客户端 ID：

```bash
sudo vowifi-vpn diagnose
```

检查某个客户端，以下用 ID `11` 举例：

```bash
sudo vowifi-vpn diagnose 11
```

诊断会显示容器、隧道接口、转发参数、端口映射及入口规则状态。指定客户端后，还会显示最近握手，并进行 5 次隧道内 ICMP 探测，输出丢包与往返时间。

诊断不会修改规则或重启服务。客户端可能屏蔽 ICMP，未响应不一定代表隧道故障；实际语音的 RTP 丢包和抖动需要在本地 SIP 软件中查看。

查看云端自动恢复记录和面板服务日志：

```bash
sudo journalctl -u vowifi-vpn-watchdog.service -n 100 --no-pager
sudo journalctl -u vowifi-vpn-panel.service -n 100 --no-pager
```

### 常见情况

| 情况 | 优先检查 |
| --- | --- |
| 面板打不开 | `/gly` 路径、TCP 80/443、安全组、证书和面板服务日志 |
| 没有 WireGuard 握手 | UDP 51820 是否放行、本地隧道是否启动、设备网络是否正常 |
| 已有握手，但 SIP 注册失败或单向无声 | 客户端公网端口段、本地 SIP/RTP 端口和绑定地址、防火墙与公网地址配置 |
| 通话卡顿、断续 | 线路丢包与抖动、上传带宽是否占满、本地 SIP 软件的媒体统计 |
| 休眠或切换网络后不恢复 | 本地程序的网络恢复、开机启动与重连逻辑 |

## 6. 稳定性机制

- **保持 NAT 映射**：客户端配置包含 `PersistentKeepalive = 25`。
- **隧道 MTU**：使用 `1380`，本地程序需保持与接入配置一致。
- **云端检查**：每轮检查结束后约 30 秒再次检查容器、WireGuard 接口、IP 转发、回程校验和本项目转发规则。
- **规则修复**：接口仍正常时，修复丢失的端口映射、入口规则和被重置的转发参数，无需重启 VPN 容器；正常规则不反复重写。
- **容器恢复**：容器或接口连续 3 次异常后尝试恢复，两次尝试至少间隔 5 分钟。客户端离线或 ICMP 未响应不会触发整台 VPN 重启。

这些机制用于减少云端配置异常造成的中断，不能代替线路质量保障。公网持续丢包、客户端休眠、网络切换、SIP 注册保活和语音抖动缓冲，需要由线路与本地项目配合处理；云端不会按未知带宽强行限速或修改正在使用的网卡队列。

## 7. 卸载

```bash
sudo vowifi-vpn uninstall
```

执行后需输入 `DELETE` 确认，将完整删除本项目程序、配置、账号、密钥、证书、客户端数据和备份。Docker、Caddy 等共享依赖保留。
